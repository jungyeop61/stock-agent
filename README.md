# 주식아

시각장애 사용자가 화면 조작 없이 음성으로 주식 계좌를 조회하고 주문할 수 있도록 만드는 음성 우선 금융 에이전트입니다.

현재 스프링 백엔드에는 토스증권 OAuth 인증과 현재가, 원화·달러 참고 환율, 미국 장 운영 일정, 계좌 목록, 보유주식 평가, 원화·달러 매수 가능 금액, 종목별 매도 가능 수량, 시장별 매매 수수료 조회가 구현되어 있습니다.
수량 기반 주문 미리보기는 데이터베이스 저장, 2분 만료, 사용자 승인, 최종 계좌 재검증과 중복 실행 차단까지 구현했습니다.
미국 주식 달러 금액 시장가 매수는 미리보기 생성·저장·조회, 2분 승인, 장 운영시간·현재가·수수료·달러 매수 가능 금액·환율의 실행 직전 재검증과 중복 실행 차단을 거쳐 `MOCK` 모드로만 실행됩니다.
제출 결과가 불명확한 수량 주문과 금액 주문은 저장된 요청 지문을 확인한 뒤 10분 안에 동일한 `clientOrderId`와 주문 내용으로 한 번만 안전 복구할 수 있습니다.
토스증권의 진행 중·종료 주문 목록과 주문 상세·누적 체결 결과를 읽기 전용으로 조회하고, 우리 서버의 주문 실행 기록도 식별값으로 조회할 수 있습니다.
토스증권에서 만든 진행 중·종료 조건 주문 목록과 조건 주문 상세도 읽기 전용으로 조회할 수 있습니다.
단일 조건 주문 생성은 현재가·수수료·계좌 여력 확인, 2분 승인과 실행 직전 재검증을 거쳐 `MOCK` 모드로만 실행됩니다.
두 매도 조건을 묶는 OCO 조건 주문도 감시가격 관계와 매도 가능 수량 확인, 2분 승인과 실행 직전 재검증을 거쳐 `MOCK` 모드로만 실행됩니다.
첫 매수 체결 뒤 매도를 감시하는 OTO 조건 주문도 매수 가능 금액 확인, 2분 승인과 실행 직전 재검증을 거쳐 `MOCK` 모드로만 실행됩니다.
조건 주문 취소도 최신 상태 조회, 2분 승인, 실행 직전 전체 조건 재검증과 대상 단위 중복 차단을 거쳐 `MOCK` 모드로만 실행됩니다.
조건 주문 정정도 원주문 전체 사본과 새 전체 조건 검증, 유형 전환, 승인, 실행 직전 재조회를 거쳐 `MOCK` 모드로만 실행됩니다.
미체결 주문 취소는 대상 조회, 2분 승인, 실행 직전 재조회와 원주문 단위 중복 차단을 거쳐 `MOCK` 모드로만 실행됩니다.
미체결 주문 정정도 국내·미국 시장별 수량·가격 규칙, 고액 주문 확인, 승인과 실행 직전 재검증을 거쳐 `MOCK` 모드로만 실행됩니다.
토스증권 주문 생성 클라이언트는 수량 주문과 미국 주식 금액 주문 형식 및 멱등성 처리를 가짜 서버로 검증했습니다.
토스증권 취소·정정 API 형식을 검증하는 내부 클라이언트를 만들었고, 일반 취소·정정 LIVE 경계에 안전정책 뒤의 호출 코드까지 준비했습니다.
실제 주문 연결 전역 안전장치는 기본 `MOCK`, LIVE 기능 비활성화, 긴급 차단 스위치 활성화와 실제 어댑터 미연결의 네 겹 차단 상태입니다.
안전 상태 API는 9개 주문 변경 기능의 LIVE 어댑터 준비 여부를 각각 공개하며, 기능별 설정도 서로 독립적으로 분리되어 있습니다.
저장소 기본값과 예시 환경 설정은 아홉 기능 모두 `false`이므로 현재는 모든 종류가 실제 토스 클라이언트 호출 전에 차단됩니다.
LIVE 주문 가능 계좌 허용 목록도 기본적으로 비어 있으며, 실행 기록을 만들기 전과 토스 클라이언트 호출 직전에 같은 계좌 검사를 반복합니다.
안전 상태 API는 허용 목록의 실제 계좌 식별값이나 개수를 공개하지 않고 설정 여부만 반환합니다.
LIVE 주문 한 건의 최대 수량과 원화·달러 주문금액 한도도 기본값이 모두 `0`이어서 실제 주문을 차단하며, 생성·정정 흐름은 최신 계산값을 실행 기록 생성 전과 토스 클라이언트 호출 직전에 반복 검사합니다.
안전 상태 API는 실제 한도 숫자를 공개하지 않고 세 한도가 모두 설정됐는지만 반환합니다.
LIVE 주문의 계좌별 한국시간 일일 누적 수량과 통화별 누적 금액 한도도 기본값이 모두 `0`이며, 토스 호출 직전 V15 데이터베이스에서 원자적으로 예약합니다.
주문 멱등성 식별값은 SHA-256 해시로만 저장하고 결과 불명 주문도 누적 예약을 유지하므로 분할 주문과 불확실한 재시도로 일일 한도를 우회할 수 없습니다.
LIVE 주문 생성·정정 종목은 `KR:005930`, `US:AAPL`처럼 시장과 함께 허용 목록에 등록해야 하며, 기본 빈 목록은 모든 신규 위험을 차단합니다.
종목 허용 검사는 내부 실행 상태 생성 전과 토스 클라이언트 호출 직전에 반복되고, 안전 상태 API에는 실제 허용 종목이나 개수를 공개하지 않습니다.
LIVE 신규 주문과 정정·복구는 토스의 진행 중 일반 주문과 조건 주문을 합산해 계좌 전체·동일 종목 활성 주문 개수 상한을 검사합니다.
활성 주문 상한은 기본값 `0`으로 닫혀 있고 목록을 확정할 수 없을 때도 안전하게 차단하므로, 주문을 여러 건 동시에 쌓는 사고를 줄입니다.
LIVE 신규 주문·정정·복구는 계좌 전체와 동일 종목의 1분 빈도도 V17 데이터베이스에서 원자적으로 예약하며, 기본값 `0`은 주문 폭주 가능성을 닫습니다.
LIVE 중앙 안전 관문의 허용·차단과 토스 변경 요청의 시작·성공·거절·결과 불명은 계좌·종목·금액·주문 식별값 없이 V16 감사 사건으로 저장하고 읽기 권한 API로 조회할 수 있습니다.
토스 변경 요청 결과 불명 사건이 하나라도 저장되면 신규 주문·정정·복구는 자동 정지되고, 위험을 줄이는 일반·조건 주문 취소만 계속 허용됩니다.
주문 상태를 토스증권에서 사람이 확인한 뒤에는 주문 권한과 확인한 최신 `UNKNOWN` 감사 사건 ID로 그 시점까지만 정지를 해제하며, 더 최신 사고가 있으면 정지를 유지합니다.
일반 수량 주문 LIVE 경계에는 토스 주문 클라이언트 연결 코드를 준비했지만 기능별 준비 상태는 계속 미연결이며, 상태 변경과 클라이언트 호출 전에 중앙 안전정책에서 차단됩니다.
미국 주식 달러 금액 주문 LIVE 경계에도 토스 주문 클라이언트 연결 코드를 준비했지만 기능별 준비 상태는 계속 미연결이며, 최신 금융 조회와 클라이언트 호출 전에 차단됩니다.
일반 미체결 주문 취소 LIVE 경계에도 토스 주문 클라이언트 연결 코드를 준비했지만 기능별 준비 상태는 계속 미연결이며, 최신 주문 재조회와 클라이언트 호출 전에 차단됩니다.
일반 미체결 주문 정정 LIVE 경계에도 토스 주문 클라이언트 연결 코드를 준비했지만 기능별 준비 상태는 계속 미연결이며, 최신 주문·현재가 재조회와 클라이언트 호출 전에 차단됩니다.
SINGLE 조건 주문 생성 LIVE 경계에도 토스 조건 주문 클라이언트 연결 코드를 준비했지만 기능별 준비 상태는 계속 미연결이며, 최신 금융 재검증과 클라이언트 호출 전에 차단됩니다.
OCO 조건 주문 생성 LIVE 경계에도 토스 조건 주문 클라이언트 연결 코드를 준비했지만 기능별 준비 상태는 계속 미연결이며, 두 매도 조건의 최신 현재가·수량·수수료 재검증과 클라이언트 호출 전에 차단됩니다.

조건 주문 취소 LIVE 경계에도 토스 조건 주문 클라이언트 연결 코드를 준비했지만 기능별 준비 상태는 계속 미연결이며, 최신 조건 주문 재조회와 클라이언트 호출 전에 차단됩니다.
조건 주문 정정 LIVE 경계에도 토스 조건 주문 클라이언트 연결 코드를 준비했지만 기능별 준비 상태는 계속 미연결이며, 원주문·현재가·계좌 여력 재조회와 기존 주문 취소·대체 주문 생성 전에 차단됩니다.
계좌·주문 API는 별도의 내부 읽기 키와 주문 키로 권한을 나누며 키가 설정되지 않으면 기본 차단됩니다.
보호 API 요청은 검증된 요청 UUID, 실제 식별값이 제거된 라우트, 요구 권한과 처리 결과만 감사 로그에 남깁니다.
따라서 지금 단계에서는 실제 매수·매도·주문 취소·주문 정정·조건 주문 생성·조건 주문 취소가 발생하지 않습니다.

파이썬 에이전트 MVP는 FastAPI, 구조화된 명령 해석, Spring API 클라이언트와 LangGraph 승인 대기 흐름까지 구현되어 있습니다.
현재가·달러 원화 참고 환율 및 통화 환산·보유자산·매수 가능 금액·수수료·매도 가능 수량·미체결 및 종료 주문·일반 주문 상세·감시 중 조건 주문과 상세·주문 실행 상태 조회, 수량 기반 매수·매도, 미국 주식 달러 금액 시장가 매수, 일반 주문 취소·정정, SINGLE·OCO·OTO 조건 주문 생성과 조건 주문 취소·정정, 결과 불명 주문 실행 복구를 지원합니다. 주문 변경은 Spring 미리보기를 만든 뒤 `승인` 또는 `취소` 응답으로만 재개되고 실행 복구도 별도 승인을 요구합니다. 국내 주식 원화 금액 주문과 금액 매도는 지원하지 않으며 미리보기 생성 전에 차단합니다. 토스증권 OpenAPI v1.2.14에는 실제 환전 거래 API가 없으므로 계좌 통화를 바꾸는 요청도 외부 호출 없이 명확히 거절합니다.
로컬 기본 명령 해석기와 Spring 주문 모드는 각각 `rules`, `MOCK`이므로 OpenAI API나 실제 증권사 주문 없이 End-to-End 안전 흐름을 테스트할 수 있습니다.
주문 명령에서 종목·수량·가격·주문번호·조건·만료일 또는 계좌 선택이 빠지면 Python Agent가 LangGraph 체크포인트에 원래 요청을 보존하고 한 항목씩 이어서 물으며, 모든 필드가 모인 뒤에만 Spring 미리보기를 생성합니다.
PostgreSQL 체크포인트 통합 테스트는 Python Agent 앱을 매 대화 차례마다 종료하고 다시 생성해도 누락 정보 수집과 기존 주문 미리보기의 승인 대기가 같은 세션에서 복구되는지 검증합니다.
같은 세션의 동시 요청은 메모리 모드에서 프로세스별 잠금으로 직렬화하고 PostgreSQL 모드에서는 여러 Agent 인스턴스가 공유하는 advisory lock으로 직렬화하여, 중복 음성 전송이나 동시 승인이 미리보기·실행을 반복하지 않도록 방어합니다.
Python Agent의 Spring 조회 요청은 일시적인 통신 장애만 제한 재시도하며, 주문 미리보기·승인·실행 POST는 결과 불명 시 자동 재전송하지 않고 사용자가 주문 상태를 확인하도록 안전하게 안내합니다.
Python Agent의 `/health`는 프로세스 생존만, `/ready`는 Spring과 활성 체크포인트 저장소 준비 상태를 확인합니다. 요청 UUID는 Spring까지 전달되며 JSON 운영 로그에는 원문 발화·인증정보·계좌 및 주문 식별값 대신 비식별 상태와 세션 해시만 기록합니다.
실제 로컬 프로세스 E2E 러너는 조회 13종·환전 거절·다중 턴 대화·일반/금액/조건 주문 변경 10종·확정 실행 복구 차단을 `Agent → Spring → 토스 읽기 스텁` 경계에서 자동 검증하며, Spring을 강제 MOCK과 LIVE 차단 상태로 실행합니다.

## 저장소 구조

- `spring-backend/`: 금융 검증, 위험 정책, 감사 로그, 주문 미리보기와 증권사 연동을 담당할 스프링 프로젝트입니다.
- `python-agent/`: 음성 명령 해석, 구조화된 의도 추출, LangGraph 대화 흐름을 담당할 파이썬 프로젝트입니다.
- `android/`: 기기 내 무료 `주식아` 호출 대기와 Python 에이전트의 전체 지원 기능을 연결한 Kotlin 네이티브 개발 앱입니다. 다중 턴 입력과 미리보기 ID에 묶인 명시적 음성 승인, Keystore 암호화 개인 토큰을 지원합니다. Agent는 개인 토큰 인증·사용자별 세션 격리·단일 프로세스 요청 제한을 적용하며 음성 API는 MOCK 안전 상태에서만 처리합니다. 실제 S22 검증과 HTTPS 운영 배포는 별도 단계입니다. 설정과 테스트는 `android/README.md`를 참고하세요.
- `deploy/`: GCP/AWS 서버 한 대용 Spring·Python·PostgreSQL·Caddy Docker 구성입니다. 2GB 메모리 제한, 개인 토큰 인증, HTTPS, 영구 체크포인트와 MOCK 고정 설정을 제공합니다. 설치·백업·이전은 `deploy/README.md`를 참고하세요.
- `docs/`: 아키텍처와 API 문서를 둘 예정입니다.

실제 증권사 주문 API는 스프링 백엔드만 호출할 수 있습니다. 파이썬 에이전트는 명령을 해석하고 주문 미리보기를 요청할 수 있지만 실제 증권사 주문을 직접 실행해서는 안 됩니다.

## 현재 개발 환경

- 스프링 백엔드: Java 21 대상, Spring Boot, Maven Wrapper
- 파이썬 에이전트: Python 3.12 이상, FastAPI, LangGraph
- 로컬 기본 데이터베이스: H2
- 통합 개발 데이터베이스: PostgreSQL

비밀키는 Git에 저장하지 않습니다. 필요한 환경변수 이름은 루트의 `.env.example`에서 확인할 수 있습니다.

## 환경 준비 순서

PostgreSQL 개발 환경을 시작합니다.

```bash
export PATH="$HOME/.docker/bin:$PATH"
docker compose up -d postgres
```

Docker Desktop 설치 직후 `docker` 명령을 찾지 못할 때는 위의 첫 번째 명령으로 경로를 현재 터미널에 반영합니다.

스프링 백엔드 의존성과 설정을 확인합니다.

```bash
cd spring-backend
./mvnw validate
```

파이썬 에이전트 가상환경과 의존성을 준비합니다.

```bash
cd python-agent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

구현된 스프링 백엔드 기능의 실행 방법과 응답 예시는 `spring-backend/README.md`에서 확인할 수 있습니다.
