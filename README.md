# 주식아

시각장애 사용자가 화면 조작 없이 음성으로 주식 계좌를 조회하고 주문할 수 있도록 만드는 음성 우선 금융 에이전트입니다.

현재 스프링 백엔드에는 토스증권 OAuth 인증과 현재가, 원화·달러 참고 환율, 미국 장 운영 일정, 계좌 목록, 보유주식 평가, 원화·달러 매수 가능 금액, 종목별 매도 가능 수량, 시장별 매매 수수료 조회가 구현되어 있습니다.
수량 기반 주문 미리보기는 데이터베이스 저장, 2분 만료, 사용자 승인, 최종 계좌 재검증과 중복 실행 차단까지 구현했습니다.
미국 주식 달러 금액 시장가 매수는 미리보기 생성·저장·조회, 2분 승인, 장 운영시간·현재가·수수료·달러 매수 가능 금액·환율의 실행 직전 재검증과 중복 실행 차단을 거쳐 `MOCK` 모드로만 실행됩니다.
제출 결과가 불명확한 수량 주문과 금액 주문은 저장된 요청 지문을 확인한 뒤 10분 안에 동일한 `clientOrderId`와 주문 내용으로 한 번만 안전 복구할 수 있습니다.
토스증권의 진행 중·종료 주문 목록과 주문 상세·누적 체결 결과를 읽기 전용으로 조회하고, 우리 서버의 주문 실행 기록도 식별값으로 조회할 수 있습니다.
토스증권에서 만든 진행 중·종료 조건 주문 목록과 조건 주문 상세도 읽기 전용으로 조회할 수 있습니다.
단일 조건 주문 생성은 현재가·수수료·계좌 여력 확인, 2분 승인과 실행 직전 재검증을 거쳐 `MOCK` 모드로만 실행됩니다.
두 매도 조건을 묶는 OCO 조건 주문도 감시가격 관계와 매도 가능 수량 확인, 2분 승인과 실행 직전 재검증을 거쳐 `MOCK` 모드로만 실행됩니다.
첫 매수 체결 뒤 매도를 감시하는 OTO 조건 주문도 매수 가능 금액 확인, 2분 승인과 실행 직전 재검증을 거쳐 `MOCK` 모드로만 실행됩니다.
조건 주문 취소도 최신 상태 조회, 2분 승인, 실행 직전 전체 조건 재검증과 대상 단위 중복 차단을 거쳐 `MOCK` 모드로만 실행됩니다.
조건 주문 정정도 원주문 전체 사본과 새 전체 조건 검증, 유형 전환, 승인, 실행 직전 재조회를 거쳐 `MOCK` 모드로만 실행됩니다.
미체결 주문 취소는 대상 조회, 2분 승인, 실행 직전 재조회와 원주문 단위 중복 차단을 거쳐 `MOCK` 모드로만 실행됩니다.
미체결 주문 정정도 국내·미국 시장별 수량·가격 규칙, 고액 주문 확인, 승인과 실행 직전 재검증을 거쳐 `MOCK` 모드로만 실행됩니다.
토스증권 주문 생성 클라이언트는 수량 주문과 미국 주식 금액 주문 형식 및 멱등성 처리를 가짜 서버로 검증했습니다.
토스증권 취소·정정 API 형식을 검증하는 내부 클라이언트도 만들었지만 실행 서비스와 연결하지 않았습니다.
실제 주문 연결 전역 안전장치는 기본 `MOCK`, LIVE 기능 비활성화, 긴급 차단 스위치 활성화와 실제 어댑터 미연결의 네 겹 차단 상태입니다.
일반 수량 주문에는 LIVE 제출 경계 골격이 추가됐지만 토스 주문 클라이언트와 연결하지 않았고 상태 변경 전 중앙 안전정책에서 차단됩니다.
미국 주식 달러 금액 주문에도 같은 LIVE 제출 경계 골격이 추가됐으며 최신 금융 조회, 미리보기 소비와 UNKNOWN 복구권 확보 전에 차단됩니다.
일반 미체결 주문 취소에도 LIVE 안전 경계가 추가됐지만 토스 주문 클라이언트와 연결하지 않았고 최신 주문 재조회와 상태 변경 전에 차단됩니다.
일반 미체결 주문 정정에도 LIVE 안전 경계가 추가됐으며 최신 주문·현재가 재조회와 상태 변경 전에 실제 정정을 차단합니다.
SINGLE 조건 주문 생성에도 LIVE 안전 경계가 추가됐지만 토스 조건 주문 클라이언트와 연결하지 않았고 최신 금융 재검증과 상태 변경 전에 차단됩니다.
OCO 조건 주문 생성에도 같은 LIVE 안전 경계가 추가됐으며 두 매도 조건의 최신 현재가·수량·수수료 재검증 전에 차단됩니다.
OTO 조건 주문 생성에도 LIVE 안전 경계가 추가됐으며 선행 매수 여력과 두 조건의 최신 금융 재검증 전에 차단됩니다.
계좌·주문 API는 별도의 내부 읽기 키와 주문 키로 권한을 나누며 키가 설정되지 않으면 기본 차단됩니다.
보호 API 요청은 검증된 요청 UUID, 실제 식별값이 제거된 라우트, 요구 권한과 처리 결과만 감사 로그에 남깁니다.
따라서 지금 단계에서는 실제 매수·매도·주문 취소·주문 정정·조건 주문 생성·조건 주문 취소가 발생하지 않습니다.

## 저장소 구조

- `spring-backend/`: 금융 검증, 위험 정책, 감사 로그, 주문 미리보기와 증권사 연동을 담당할 스프링 프로젝트입니다.
- `python-agent/`: 음성 명령 해석, 구조화된 의도 추출, LangGraph 대화 흐름을 담당할 파이썬 프로젝트입니다.
- `android/`: 음성 우선 Android 앱을 둘 예정입니다.
- `infra/`: 로컬 및 클라우드 배포 설정을 둘 예정입니다.
- `docs/`: 아키텍처와 API 문서를 둘 예정입니다.

실제 증권사 주문 API는 스프링 백엔드만 호출할 수 있습니다. 파이썬 에이전트는 명령을 해석하고 주문 미리보기를 요청할 수 있지만 실제 증권사 주문을 직접 실행해서는 안 됩니다.

## 현재 개발 환경

- 스프링 백엔드: Java 21 대상, Spring Boot, Maven Wrapper
- 파이썬 에이전트: Python 3.12 이상, FastAPI, LangGraph
- 로컬 기본 데이터베이스: H2
- 통합 개발 데이터베이스: PostgreSQL

비밀키는 Git에 저장하지 않습니다. 필요한 환경변수 이름은 루트의 `.env.example`에서 확인할 수 있습니다.

## 환경 준비 순서

PostgreSQL 개발 환경을 시작합니다.

```bash
export PATH="$HOME/.docker/bin:$PATH"
docker compose up -d postgres
```

Docker Desktop 설치 직후 `docker` 명령을 찾지 못할 때는 위의 첫 번째 명령으로 경로를 현재 터미널에 반영합니다.

스프링 백엔드 의존성과 설정을 확인합니다.

```bash
cd spring-backend
./mvnw validate
```

파이썬 에이전트 가상환경과 의존성을 준비합니다.

```bash
cd python-agent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

구현된 스프링 백엔드 기능의 실행 방법과 응답 예시는 `spring-backend/README.md`에서 확인할 수 있습니다.
